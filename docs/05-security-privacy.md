# 05. Безпека і приватність

## 1. Принципи

1. Учні не пишуть у базу; пише лише автентифікований вчитель.
2. Дані учня непідбираємі за межами посилання: доступ за UUID v4 (122 біти).
3. У базі немає персональних даних (імена, контакти, фото, клас, школа, вільний текст).
4. Правила Firestore це остання лінія захисту: навіть помилка в UI не повинна дозволити від'ємний баланс чи зміну журналу.

## 2. Security Rules (повний код)

```
rules_version = '2';
service cloud.firestore {
  match /databases/{db}/documents {

    function isTeacher() {
      return request.auth != null &&
             exists(/databases/$(db)/documents/admins/$(request.auth.uid));
    }
    function isUuid(id) {
      return id.matches('^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$');
    }
    function validProfile(d) {
      return d.keys().hasOnly(['alias','archived','balance','earned','recent','hot','last',
                               'lastOp','lastAt','stats','counters','achievements','v'])
          && d.alias is string && d.alias.size() > 0 && d.alias.size() <= 24
          && d.balance is int && d.balance >= 0
          && d.earned  is int && d.earned  >= 0
          && d.v is int;
    }
    function validOp(d) {
      return d.type in ['credit','redeem','quest','adjust','void']
          && d.delta is int
          && d.ts == request.time
          && d.prev is map;
    }

    // Конфігурація: публічне читання опублікованого, решта лише вчитель
    match /config/published { allow read: if true; allow write: if isTeacher(); }
    match /config/stock     { allow read: if true; allow write: if isTeacher(); }
    match /config/{other}   { allow read, write: if isTeacher(); }
    match /config_history/{v} { allow read, write: if isTeacher(); }

    // Аудит: лише додавання
    match /audit/{id} { allow read, create: if isTeacher(); allow update, delete: if false; }

    // Адміністратори: створюються вручну в консолі
    match /admins/{uid} {
      allow read: if request.auth != null && request.auth.uid == uid;
      allow write: if false;
    }

    match /profiles/{pid} {
      allow get: if isUuid(pid);                    // за точним UUID
      allow list: if isTeacher();                   // перелік заборонено всім, крім вчителя
      allow create: if isTeacher() && isUuid(pid)
                    && validProfile(request.resource.data) && request.resource.data.v == 1;
      allow update: if isTeacher() && validProfile(request.resource.data)
                    && request.resource.data.v == resource.data.v + 1;   // оптимістичне блокування
      allow delete: if isTeacher();

      match /ledger/{opId} {
        // читання лише поки профіль існує: після видалення/перевипуску старе посилання нічого не показує
        allow read: if isUuid(pid) && exists(/databases/$(db)/documents/profiles/$(pid));
        allow create: if isTeacher() && validOp(request.resource.data);
        allow update, delete: if false;             // журнал незмінний
      }
    }
  }
}
```

**Примітки.**
- Не додавайте правил для collection-group-запитів: перелічити всі журнали одним запитом не повинно бути можливо.
- Журнал незмінний, тому клієнт його не видаляє. Видалення профілю (наприклад, при перевипуску посилання) лишає «осиротілі» документи журналу, але вони **нечитабельні**, бо правило читання вимагає існування профілю. Рекомендація: замість видалення архівувати профіль (`archived: true`); повне очищення осиротілих даних робити вручну в консолі Firebase.
- Правило `exists()` додає одне читання на запит журналу; на квоти це не впливає.
- Для `d.ts == request.time` клієнт має писати `serverTimestamp()`.
- Адміністратори додаються лише вручну в консолі Firebase (`admins/{uid}`), не з клієнта.

## 3. Тести Rules (емулятор, `@firebase/rules-unit-testing`)

| № | Сценарій | Очікування |
|---|---|---|
| R1 | Анонім читає `config/published` | дозволено |
| R2 | Анонім пише в `config/published` | відхилено |
| R3 | Анонім читає `profiles/<валідний uuid>` | дозволено |
| R4 | Анонім читає `profiles/не-uuid` | відхилено |
| R5 | Анонім виконує `list` по `profiles` | відхилено |
| R6 | Анонім пише в `profiles/*` | відхилено |
| R7 | Вчитель (є в `admins`) створює профіль із `v: 1` | дозволено |
| R8 | Вчитель створює профіль з `v: 2` або з невідомим полем | відхилено |
| R9 | Вчитель оновлює профіль із `v` не на 1 більшим | відхилено |
| R10 | Вчитель встановлює `balance: -1` | відхилено |
| R11 | Вчитель створює документ журналу з коректним `ts` | дозволено |
| R12 | Вчитель повторно створює документ журналу з тим самим `opId` | відхилено |
| R13 | Вчитель змінює/видаляє документ журналу | відхилено |
| R14 | Автентифікований користувач **без** запису в `admins` пише в профіль | відхилено |
| R15 | Анонім читає `config/draft`, `config_history/*`, `audit/*` | відхилено |
| R16 | Анонім читає журнал `profiles/<uuid>/ledger` існуючого профілю | дозволено (лише за відомим UUID) |
| R17 | Анонім читає журнал профілю, якого вже не існує (видалено) | відхилено |

## 4. Модель загроз

| Загроза | Ймовірність | Захист |
|---|---|---|
| Учень вигадує оцінку | середня | вчитель звіряє зі щоденником, підпис у щоденнику; QR не містить оцінок |
| Повторне пред'явлення тієї ж оцінки | середня | підпис у щоденнику; м'яке застереження про повтор у застосунку; `opId` не дає зарахувати двічі при подвійному тапі |
| Чужий QR (сфотографована картка, чужий телефон) | низька | панель показує псевдонім і локальні ініціали; вчитель перевіряє очима; нагороду видає вчитель |
| Витік посилання | низька | доступ лише на читання балансу; перевипуск UUID |
| Підбір UUID | практично нульова | 122 біти випадковості; перелік профілів заборонений |
| Спам у базу від сторонніх | немає | учні не мають запису взагалі |
| Помилка вчителя | середня | скасування останньої операції, коригування, журнал, перевірка цілісності |
| Втрата акаунта вчителя | низька | щотижневий експорт JSON; резервний адміністратор |
| Одночасна робота з двох пристроїв | низька | оптимістичне блокування `v` у Rules і транзакції |
| Витік даних із репозиторію | низька | у репозиторії лише публічна конфігурація Firebase; таблиці учнів немає; перевірка перед кожним пушем |

## 5. Приватність

**Зберігається:** UUID, псевдонім, баланс, «зароблено всього», журнал (оцінка, зірки, дата, ручні події), конфігурація.
**Не зберігається:** імена, email, телефони, фото, клас, школа, вільний текст.
**Локально у вчителя (за бажанням):** довідка «псевдонім → ініціали/ім'я» в IndexedDB; ніколи не синхронізується; експорт лише зашифрованим файлом (WebCrypto: PBKDF2 + AES-GCM, пароль задає вчитель).

**Застереження.** Це **псевдонімізація, а не анонімізація.** Учитель знає, кому належить профіль; діти знають свій псевдонім; журнал містить оцінки. Тому за суттю це персональні дані (оцінки навчальних досягнень). Рекомендації:

1. Мінімум даних: не додавайте поля, які не потрібні для логіки.
2. Не публікуйте посилання й картки.
3. Жодних публічних рейтингів і спільних екранів.
4. **Повідомте батьків** про систему (що зберігається, чого не зберігається, як вона працює) і дайте можливість відмовитися (альтернативна нагорода без застосунку).
5. Використання Google/Firebase (сторонньої хмари) варто описати в повідомленні батькам.

Погодження з директором, за словами власника, не потрібне. Це не юридична консультація; за потреби уточніть вимоги українського закону про захист персональних даних у юриста або відповідальної особи школи.

## 6. Чекліст перед запуском

- [ ] Rules розгорнуті; усі тести R1–R17 проходять на емуляторі.
- [ ] У `admins` лише потрібні UID; реєстрація сторонніх користувачів у Auth вимкнена (вхід лише для вчителя).
- [ ] У репозиторії немає імен, таблиць учнів, ключів (крім публічної веб-конфігурації Firebase).
- [ ] Немає аналітики, зовнішніх шрифтів, CDN (окрім Firebase SDK).
- [ ] Картки надруковані; «таблиця псевдонімів» зберігається окремо від застосунку.
- [ ] Батьків повідомлено.
- [ ] Експорт і відновлення з нього перевірені.
- [ ] Перевірка цілісності проходить без розбіжностей.
- [ ] Сканер перевірений на реальних iOS і Android.
- [ ] (Необов'язково) App Check налаштовано.
