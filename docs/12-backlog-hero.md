# 12. Відкладено: «Герой» (аватар і речі)

**Статус: не реалізувати в MVP** (рішення власника D12). Файл зберігає специфікацію, щоб архітектура її не заблокувала.

## 1. Ідея

Персоналізація профілю учня: вибір персонажа й речей (шапки, обличчя, фони, рамки, титули) у стилі простої плоскої 2D-векторної графіки (за мотивами Kahoot). Пізніше речі можна купувати за зірки ✦.

## 2. Модель

- Шари SVG у фіксованому порядку (знизу вгору): `bg` → `base` → `face` → `hat` → `hold` → `frame`; окремо `title`.
- Один файл `assets/hero/sprite.svg` із `<symbol>`; складання через `<use href="#...">` на полотні 200×200 з якорями (голова, обличчя, руки).
- Колір через CSS-змінні (`--c1`, `--c2`): один малюнок дає багато варіантів.
- Стиль: плоскі заливки, без градієнтів, заокруглена геометрія, 2–3 товщини обведення, палітра до 5 кольорів на річ, 0,5–2 КБ на річ.
- Мінімальний каталог: 4 персонажі × 6 кольорів, 10 шапок, 6 облич, 5 фонів, 4 рамки (29 малюнків).
- Альтернатива: генерувати персонажів кодом із геометричних примітивів.

## 3. Економіка

| Рідкість | Орієнтовна ціна | Приклади |
|---|---|---|
| Базові | безкоштовно | 4 персонажі, базові кольори |
| Звичайні | 6–10 ✦ | шапки, фони |
| Рідкісні | 15–25 ✦ | рамки |
| Епічні | 17–40 ✦ | комплекти |

Речі коштують вчителю 0 грн, тому кожна зірка, витрачена на них замість смаколика, зменшує бюджет (≈ 50–60 грн/міс на кожні 15 % зірок за моделлю `02-economy.md`). Без випадковості: ціна детермінована. Частина речей відкривається безкоштовно за рівнями й досягненнями. Вся персоналізація приватна (галерей і рейтингів немає).

## 4. Дані та права (на майбутнє)

- До профілю додати `owned: string[]` (список відкритих/куплених речей); пише вчитель.
- Окремий документ `profiles/{uuid}/wardrobe/hero` (вдягнене): може писати власник посилання, але лише речі зі списку `owned` (Rules перевіряють через `get()` профілю). Приклад функцій:

```
function okSlot(d, k, owned) { return !(k in d.keys()) || d[k] == null || d[k] in owned; }
function validHero(d, pid) {
  let owned = get(/databases/$(db)/documents/profiles/$(pid)).data.owned;
  return d.keys().hasOnly(['base','color','bg','face','hat','hold','frame','title'])
      && okSlot(d,'base',owned) && okSlot(d,'bg',owned) && okSlot(d,'face',owned)
      && okSlot(d,'hat',owned)  && okSlot(d,'hold',owned) && okSlot(d,'frame',owned)
      && okSlot(d,'title',owned);
}
match /wardrobe/{doc} { allow read: if isUuid(pid) && exists(...profile...);
                        allow write: if isUuid(pid) && doc == 'hero' && validHero(request.resource.data, pid); }
```

Перед запуском обов'язково протестувати в емуляторі Firebase.
- У `redeem` додати вид позиції `kind: 'cosmetic'`: при покупці річ додається в `owned` (повторна покупка заборонена); каталог речей `cosmetics[]` у `config/published`.
- Досягнення (`achievements`) можуть розблоковувати речі.

## 5. Вимоги до MVP для сумісності

1. Профіль має версію схеми (`config/published.schema`) і міграційний механізм (`04-data-model.md §7`).
2. UI не повинен припускати фіксований набір полів профілю; дані читаються явно.
3. `redeem` приймає позицію як параметр, а не жорстко прописані ідентифікатори.
4. Зберігайте поле `achievements` у профілі (порожнє).
5. Rules: коли додаватиметься `wardrobe`, не послаблювати існуючі правила.

## 6. Ризики

| Ризик | Рішення |
|---|---|
| Обсяг графіки | мінімальний каталог, колір змінними, генерація кодом |
| Нерівність за «крутістю» | безкоштовні розблокування за рівнем, приватність |
| Ліцензії художніх наборів | власні малюнки або перевірені відкриті ліцензії (CC0/CC BY/CC BY-SA мають різні вимоги), ведення списку авторів; не копіювати графіку Kahoot |
| Складність Rules | реалізувати після MVP, перевірити в емуляторі |
