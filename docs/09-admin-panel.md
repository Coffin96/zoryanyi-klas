# 09. Адмінпанель вчителя

Адмінпанель це розділ застосунку вчителя (`teacher/#/admin/...`). Доступна лише користувачам із запису в `admins`.

## 1. Модулі

| Розділ | Можливості |
|---|---|
| **Учні** | створити пачкою (UUID + псевдоніми), друк карток, змінити псевдонім, перевипустити посилання, архівувати, коригувати баланс (з причиною), переглянути журнал, локальна довідка імен |
| **Магазин** | додати, змінити, дублювати, архівувати, видалити позиції; ціни, ліміти, запас, період доступності, `unitCost` |
| **Квести** | створення з шаблонів, параметри, вмикання/вимикання; ручна нагорода «Внесок» (одному й масово) |
| **Оцінки й рівні** | таблиця «оцінка → ✦» (від неї залежать кнопки клавіатури), пороги й назви рівнів |
| **Налаштування** | назва/символ валюти, `dupWindowMin`, `undoSeconds`, `yearEnd`, `refItem`, `budgetAlertUah`, `questMonthlyCap`, новини класу |
| **Бюджет** | вартість зірки, видано за період, порівняння зі «старою» системою, прогноз потреби, симулятор |
| **Журнал і аудит** | події профілів, скасування, історія змін конфігурації |
| **Дані** | експорт/імпорт JSON, перевірка цілісності, перерахунок з журналу, нагадування про резервну копію |
| **Доступи** | список адміністраторів |

## 2. Життєвий цикл конфігурації

```
Чернетка (config/draft) → автоперевірка (validateConfig) → публікація (config/published) → знімок (config_history/{v})
```

- Усі зміни в розділах «Магазин», «Квести», «Оцінки й рівні», «Налаштування» потрапляють у **чернетку**; учні бачать лише опубліковане.
- Кнопка «Опублікувати» неактивна, поки є помилки (`error`); попередження (`warn`) показуються, але не блокують.
- Публікація: `version + 1`, запис у `config/published`, знімок у `config_history/{version}` (зберігається 20 останніх), запис `audit`.
- **Відкат:** вибір знімка → «Відновити як чернетку» → «Опублікувати».
- **Відкладене застосування цін:** підвищення ціни діє з вибраної дати (за замовчуванням наступний понеділок); зниження діє одразу. Реалізація: у позиції поле `priceSchedule: [{from: 'YYYY-MM-DD', price: N}]`; клієнт обирає чинну ціну за київською датою.
- **Новини:** публікація може додати запис у `news` («Нове» в учнів).

## 3. Автоперевірка конфігурації (`validateConfig`)

| Рівень | Правило |
|---|---|
| error | `id` позицій і квестів унікальні; формат `[a-z0-9_]{2,24}` |
| error | `price` ціле ≥ 1; `unitCost` ≥ 0 |
| error | `grades` містить ключі 7–12 (або підмножину) із цілими ≥ 0 |
| error | `levels`: перший `min: 0`, `min` строго зростає |
| error | `quests[].params` у допустимих межах (`window` ≥ `minHistory` ≥ 1, `delta` ≥ 0, `length` ≥ 1, `windowDays` ≥ 1) |
| error | `settings.yearEnd` валідна дата в майбутньому |
| error | є принаймні одна активна позиція типу `sweet` |
| error | `refItem` існує й має `unitCost > 0` |
| warn | **перекіс:** грн за ✦ позиції `sweet` вище за `refPerStar` більш ніж на 25 %, а `acceptSubsidy` не ввімкнено |
| warn | позиція з `unitCost > 0`, але без `limits` і ціною нижчою за паритет на > 50 % (дуже висока субсидія) |
| warn | `questMonthlyCap` > 12 (квести складають занадто велику частку потоку) |
| info | субсидія позиції: `subsidy = 1 − price × refPerStar / unitCost` показується як бейдж |

`refPerStar = unitCost(refItem) / price(refItem)`.

## 4. Магазин

**Список позицій:** іконка, назва, тип, ціна, ліміти, запас, `грн/✦`, субсидія, статус (активна/архів). Перетягування для порядку (`order`).

**Форма позиції:** `id` (незмінний після створення), `name`, `icon` (емодзі), `description`, `kind`, `price`, `limits` (`perMonth`, `cooldownDays`, `perDay`, `total`), `stock` (число або «необмежено»; зберігається в `config/stock`), `window` (період доступності), `unitCost` (або `pricePerKg` і `pcsPerKg`, з яких рахується `unitCost`), `acceptSubsidy`, `active`.

**Операції:**

| Дія | Правило |
|---|---|
| Додати / дублювати | нова позиція отримує «рекомендовану ціну» (`recommendPrice`) |
| Змінити ціну | панель показує ефект: нову вартість зірки, субсидію, скільки учнів зараз можуть/не можуть купити |
| Архівувати | позиція зникає в учнів, історія лишається (рекомендовано замість видалення) |
| Видалити | лише якщо позицію жодного разу не видавали (перевірка за журналами); інакше пропонується архівація |
| Масова зміна | «Помножити всі ціни на коефіцієнт» з округленням до цілого |
| Запас | кнопки «+N / −N», автоматичне зменшення при видачі, при 0 позиція показується як «закінчилось» |

## 5. Квести

Квест = шаблон + параметри. Шаблони: `growth`, `streak`, `manual`. Спільні поля: `title`, `icon`, `description`, `reward`, `perMonth`, `active`, `from`/`to` (необов'язково).

- **Створення ручного квесту** займає секунди: назва, нагорода, ліміт; з'являється кнопка в панелі учня й у масових діях.
- **Масово «Внесок»:** вибір учнів зі списку → «Нарахувати»; ліміти застосовуються автоматично; звіт «Нараховано N, ліміт у M».
- Зміна параметрів впливає лише на майбутні нарахування.
- Загальний `questMonthlyCap` у «Налаштуваннях».

## 6. Оцінки й рівні

- Таблиця `grades`: кнопки клавіатури вчителя генеруються з ключів; зміна шкали діє на майбутні зарахування (минулі події не перераховуються).
- Рівні: назва й поріг; попередній перегляд «скільки учнів на якому рівні».

## 7. Учні

| Функція | Деталі |
|---|---|
| Створення пачкою | кількість → UUID v4 + унікальні псевдоніми (тварина + число), без дублів; `v: 1`, нульові лічильники |
| Друк карток | вибір учнів → `print.css` (A4, 6–8 карток) |
| Коригування | ±N ✦, причина зі списку, створює `adjust` |
| Перевипуск посилання | транзакція: копія профілю й журналу під новий UUID, старий профіль видаляється (журнал лишається нечитабельним, `05-security-privacy.md`), запис `audit` |
| Архівація | `archived: true`; приховано зі списків і прогнозів |
| **Локальна довідка імен** | «псевдонім → ініціали/ім'я» в IndexedDB браузера вчителя; показується в панелі учня; **ніколи не відправляється у Firebase**; експорт/імпорт лише зашифрованим файлом (WebCrypto, пароль вчителя); за відсутності довідки застосунок працює без неї |

## 8. Бюджет

| Показник | Як рахується |
|---|---|
| Видано за період | кількість за позиціями (з журналу `redeem`, мінус `void`) |
| Вартість у грн | `Σ(видано × unitCost)` |
| Фактична вартість зірки | `вартість / Σ витрачених ✦` |
| Порівняння зі «старою» | кількість зарахованих оцінок ≥ 10 × `unitCost(caramel)` |
| Прогноз потреби | `forecastDemand` (верхня межа на день видачі) |
| Поріг | якщо місячна вартість > `budgetAlertUah`, показується попередження з порадами (`cooldownDays`, ціна, `questMonthlyCap`) |
| Симулятор | змінюєте ціни/ліміти в чернетці → бачите розрахункову місячну вартість на фактичному потоці за останні N тижнів |

Дані для бюджету читаються з журналів профілів; щоб не перевищувати квоти, агрегати за місяць кешуються в `localStorage` вчителя й перераховуються за запитом.

## 9. Журнал і аудит

- **Журнал профілю:** події, фільтр за типом, позначка «скасовано», кнопка «Скасувати» лише для останньої операції.
- **Аудит (`audit`):** публікації конфігурації, відновлення знімків, коригування, перевипуски, імпорти. Поля: `ts`, `by` (UID), `action`, короткий опис (без персональних даних).

## 10. Дані

- **Експорт:** один JSON (`04-data-model.md §8`); нагадування раз на тиждень при відкритті панелі («Остання копія 9 днів тому»).
- **Імпорт:** перевірка `schema`, попередній перегляд відмінностей, підтвердження; перед імпортом автоматичний експорт поточного стану.
- **Перевірка цілісності:** `Σ delta == balance`, `earned` за журналом; список розбіжностей; «Перерахувати з журналу» після підтвердження.
- **Міграція схеми:** кнопка запускає `migrate.js` після автоматичного експорту.

## 11. Доступи

Список UID адміністраторів. **Додавання нового адміністратора** виконується вручну в консолі Firebase (Rules забороняють запис у `admins` із клієнта). Панель показує поточний список і інструкцію.

## 12. Вимоги до реалізації

- Кожна зміна конфігурації попередньо валідується локально (`validateConfig`) і відображає помилки біля полів.
- Дії, що незворотні (видалення, імпорт), потребують підтвердження; решта має скасування або чернетку.
- Форми доступні з клавіатури, мобільна версія повноцінна (планшет бажаний, але не обов'язковий).
